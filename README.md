# Vybe

UI/UX-прототип мессенджера с голосовыми каналами: собственная визуальная
идентичность, три темы (dark / light / amoled),
навигация серверы → каналы → чат, экран регистрации/входа, голосовой
экран с живой осциллограммой голоса.

Это прототип интерфейса: чат, голос и регистрация работают на локальных
демо-данных, без настоящего сетевого бэкенда — несколько человек через
это приложение пока не могут переписываться между собой через интернет.

## Разработка

```bash
npm install
npm start          # запустить в режиме разработки
```

## Сборка установщика под Windows

```bash
npm run dist:win
```

Результат — `dist/Vybe-Setup-<версия>.exe` (NSIS-установщик; именно
установщик, а не portable-файл — это нужно для авто-обновления).

## Авто-обновление (electron-updater + GitHub Releases)

Приложение при каждом запуске (только в собранной версии, не в `npm start`)
тихо проверяет GitHub Releases этого репозитория. Если там опубликован
релиз с версией выше текущей — обновление само скачивается в фоне, и при
готовности пользователю предлагается перезапустить приложение.

### Как выпустить новую версию

1. Поднять версию в `package.json` (поле `"version"`), например `1.0.0` → `1.0.1`.
2. Закоммитить изменения.
3. Собрать и сразу опубликовать релиз на GitHub одной командой:
   ```bash
   GH_TOKEN=<ваш_github_token> npm run dist:win:publish
   ```
   `GH_TOKEN` — [personal access token](https://github.com/settings/tokens)
   с правом `repo` (для публикации релизов в этом репозитории).
4. Все установленные копии Vybe сами обнаружат новую версию при следующем
   запуске (или проверке) и обновятся.

Если собрать и опубликовать нужно раздельно — `npm run dist:win` только
собирает `.exe` в `dist/`, а публикацию на GitHub можно сделать вручную
через веб-интерфейс GitHub Releases, загрузив туда файлы из `dist/`
(обязательно `latest.yml` вместе с `.exe` — именно по нему electron-updater
узнаёт номер последней версии).
